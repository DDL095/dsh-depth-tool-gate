## R1 会话间沟通拓扑不完整

**状态**：待决 —— 用户 2026-11-15 已阅并明确「这个岔路先不处理」，转为登记。

### 问题（实测）

当前拓扑：

```
        ┌─────────────┐
        │  父 / 主会话  │  ← 唯一出口
        └──────┬──────┘
     ┌─────────┼─────────┐
  ┌──▼──┐  ┌──▼──┐  ┌──▼──┐
  │ 子A  │  │ 子B  │  │ 子C  │   ← 兄弟
  └─────┘  └─────┘  └─────┘
```

**兄弟之间没有直连通道。** 宿主 `send_message` 只允许两条路径
（`dsh-subagent/lib/index.js:1544-1556`）：

1. 收件人是**你的直接子代**；
2. 收件人是**你的直接父代**（且你必须是 resident continuable 子代）。

发往兄弟 ⇒ 落进 `deliverToChild(sender, targetId, …)` ⇒ 目标非自己的直接子代
⇒ 被邻接校验拒（`UNAUTHORIZED`）。

**后果**：兄弟协同只能 A → 父 → B **两跳**，每跳内容都进父会话上下文 ⇒
父会话膨胀 + 信息两跳衰减/变形。

### 为什么现在不做

用户 2026-11-15 裁定：「这个岔路先不处理吧，先把新用户的框架整理好」。
且这是 `[宿主级]` 改动（改 `dsh-subagent` 服务层），须走沙箱七步 + MoA 盲审。

### 要做的话

- 改动位置：宿主 `dsh-subagent` 的 `sendMessage` 邻接校验（放宽到「同一父下的兄弟」）
- 需要新增概念：兄弟消息的**路由与归属**（谁有权发起、是否需要父授权、如何防环）
- 风险：编排风暴（兄弟互发成环）、父失去可见性（子代理树活动对父不可见）

## R2 回执分层：结论 / 证据分离

**状态**：待决（与 R1 同批搁置）

### 问题（实测）

`subagent` / `dispatch_composed` 的回执是**全量文本**：子代查完的东西**过程与结论一起**
灌进父会话。用户 2026-11-15 描述：「现在所有的 LLM 都偏向于如果有工具就在单独的会话内完成，
导致整个上下文非常冗长」。

### 与 R1 的关系

两者是同一问题的两面：**R1 治「通信路径」，R2 治「通信内容」**。
R1 不做的话，兄弟协同全靠父中转，父的膨胀更严重 ⇒ **R2 的收益在 R1 之后更大**。

### 候选形态

| 形态 | 做法 | 代价 |
|---|---|---|
| B1 | 子代回执分「结论（≤N 行）+ 证据（按需查）」，父默认只收结论 | 需要子代侧配合产出结构化回执（插件可做：子代是 dtg 管的） |
| B2 | 证据落盘 + 回执只给路径与摘要 | 需要落盘约定与路径可达性（跨会话文件系统） |
| B3 | 回执加「可折叠」标记，由宿主渲染层折叠 | 需要宿主支持（`[宿主级]`） |

### 要做的话

- 插件内可做：改 `dispatch_composed` 的 `execute` / 回执封装 + `agents-briefs/` 的回执规范
- 必须有**变异通道**：回执变短 ⇒ 对应探针必须转红

## R3 上下文水位对模型可见

**状态**：待决

### 问题（实测）

宿主 agent-loop 内部有 `tokenUsage`（`dsh-agent-loop/lib/index.js` 等处可见），
但**未透给模型** ⇒ 模型看不到「本会话已用 X%」。

⇒ **派单没有被理性看待**：从模型视角，「在已有工具的前提下自己查」= 零额外启动成本；
派一个 subagent = 一次完整 LLM 会话 + 工具面税（实测 reader 面 9 件 / cordis-deep 99 件，
每次都要重述）。**除非派单能显著省上下文，否则模型永远选本会话** ——
这是**激励错配**，不是提示词能改的。

### 要做的话

- `[宿主级]`：把上下文水位注入模型可见上下文（或作为工具返回值）
- 与 R2 配合：水位可见 ⇒ 模型才会主动派单；R2 让派单的回执更划算

**状态**：暂不做（已有结论，见 `preset-policy.md` §档 2）

## R6 `preset_allow` 子代侧双义彻底拆

**状态**：部分完成

`preset_allow[p]` 在**两侧语义不同**：

| 侧 | 语义 | 强度 |
|---|---|---|
| 子代（depth>0） | 对 `baseline_deny ∪ pending` 的**豁免集** | 黑名单弱 |
| 主会话（depth0） | 回落读时当 **keep-only 正面清单** | keep-only 强 |

**已做**：主会话侧可用 `main_preset_allow[p]` 显式拆分（`resolveMainAllow` 的
`pick-first-valid` 语义；配齐即生效，且 `allowFallbacks()` 面板对账可见）。
`cordis-router` 已完成拆分（2026-11-15）。

**未做**：**取消主会话侧的回落读**（彻底断掉双语义）。
现状仍回落的 5 个域 preset：`illus-deep` / `aigen-deep` / `ppt-deep` / `excel-deep` /
`word-deep` —— 它们是**正向白名单**语义（豁免域工具为主），与 router 的编排面性质不同，
是否拆分取决于各自面内容。

**风险**：直接取消回落 ⇒ 未拆分的 preset 主会话面**突变**（router 曾是 19→20 件级别）。
⇒ 迁移须走「显式、可见、可回滚」四步（`preset-policy.md` §10.3 已写明）。
